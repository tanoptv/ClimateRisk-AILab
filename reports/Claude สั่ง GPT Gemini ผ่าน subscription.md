# Claude Code สั่ง Codex ได้ แต่ Gemini ติดกำแพง

> **คำเตือนสำคัญเรื่องหลักฐาน:** ในซานด์บ็อกซ์วิจัยนี้ **ไม่สามารถเปิดเอกสารหลักของ OpenAI และ Google ได้** (โฮสต์ `developers.openai.com`, `help.openai.com`, `geminicli.com`, `developers.google.com`, `antigravity.google`, `discuss.ai.google.dev` ถูกบล็อก) ข้อมูลฝั่ง Codex/ChatGPT จึงมาจากสรุปผลการค้นหาและบล็อกบุคคลที่สามเป็นหลัก ส่วนฝั่ง Gemini ใช้ได้เฉพาะไฟล์เอกสารใน GitHub repo ของ Google เอง (raw.githubusercontent.com) เอกสารฝั่ง Anthropic (`code.claude.com`) อ่านได้โดยตรง แต่เครื่องมือ fetch คืนค่าเป็นข้อความที่สรุปผ่านโมเดล ไม่ใช่ HTML ดิบ คำพูดในเครื่องหมายคำพูดจึงควรตรวจซ้ำกับหน้าต้นทางก่อนใช้ตัดสินใจจริง รายงานนี้แยกป้าย **[ยืนยัน]** (อ้างจากเอกสารหลักของผู้ให้บริการที่อ่านได้) และ **[ไม่ยืนยัน]** (แหล่งรอง ผลค้นหา บล็อก หรือข้อสรุปของผู้วิจัยเอง) ไว้ตลอดทาง

## สรุปผู้บริหาร: ทำได้จริงกับ Codex แต่ Gemini แบบ subscription ไม่ควรทำ

**ทำได้ในทางเทคนิค โดยไม่ต้องให้ผู้ใช้ชี้ไฟล์ md เอง** Claude Code เรียก `codex exec` ผ่าน Bash แล้วรับคำตอบกลับเป็นผลลัพธ์ของเครื่องมือโดยตรง จากนั้นสรุปต่อได้ในรอบเดียวกัน ไม่ต้องมีโฟลเดอร์ส่งข้อความ ฝั่ง Codex นี่เป็นเส้นทางที่ความเสี่ยงต่ำที่สุดและใช้ล็อกอิน ChatGPT Plus/Pro ได้ตาม README ของ OpenAI [ยืนยัน] ([openai/codex README](https://github.com/openai/codex/blob/main/README.md)) ส่วนฝั่ง Gemini สถานการณ์ต่างออกไปมาก: repo ของ Gemini CLI ประกาศว่า "Free individual access and Google AI Pro / Ultra (Google One) moved to Antigravity CLI on June 18, 2026" [ยืนยัน] ([google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli)) แปลว่าการล็อกอินด้วยบัญชี Google AI Pro/Ultra ผ่าน Gemini CLI แบบ headless น่าจะใช้ไม่ได้อีกแล้ว ขณะที่ Antigravity CLI (`agy`) มีรายงานบั๊ก `agy -p` ค้างในสภาพแวดล้อมไม่มี TTY และเจ้าหน้าที่ฟอรัม Google (แหล่งรอง [ไม่ยืนยัน]) ระบุว่าการให้เอเจนต์บุคคลที่สามอย่าง Claude Code ครอบ `agy` ภายใต้ล็อกอินผู้บริโภคเป็นการใช้งานที่ไม่รองรับ และอาจถูกบังคับใช้ ToS อัตโนมัติ ความเสี่ยงแบน Google สูงสุดในสามเจ้า เพราะมีการแบนจริงเมื่อ ก.พ. 2026 ซึ่งผู้ดูแลของ Google ยืนยันเอง [ยืนยัน] ([Discussion #20632](https://github.com/google-gemini/gemini-cli/discussions/20632)) **คำแนะนำ:** ใช้ Claude Code + Codex ผ่าน wrapper script ที่ล็อกค่า sandbox, timeout และโควตา เป็นแกนหลัก ส่วน Gemini ให้ใช้ API key จาก AI Studio/Vertex (จ่ายตามใช้ ซึ่งผิดข้อกำหนด "ไม่ใช้ API" ของคุณ แต่เป็นทางเดียวที่เอกสารรองรับ) หรือตัดออก ทั้งนี้ "ถามความเห็นที่สอง" ที่ถูกกว่าและเรียบง่ายกว่าคือ subagent ของ Claude เองบนโมเดลเล็ก

## กลไกที่ใช้ได้จริง: Bash wrapper ชนะ MCP และ agent teams

กลไกที่ง่ายและเสี่ยงน้อยที่สุดคือให้ Claude Code เรียก CLI ของอีกฝั่งผ่าน Bash แล้วอ่านผลจาก stdout ฝั่ง Codex มีโหมด non-interactive `codex exec PROMPT` โดยเอกสารทางการระบุ `--json` (JSONL), `-o/--output-last-message` และ `--output-schema` แต่ข้อมูลนี้มาจากสรุปผลค้นหาของหน้า developers.openai.com ที่เปิดตรงไม่ได้ [ไม่ยืนยัน] ([Non-interactive mode](https://developers.openai.com/codex/noninteractive)) ส่วนชื่อ flag ของ sandbox/approval (`--sandbox read-only`, `--full-auto`, `--skip-git-repo-check`) ยังไม่ได้ตรวจกับเอกสารหลักเลย ฝั่ง Gemini CLI มี `gemini -p "..."` พร้อม `--output-format json` และ `stream-json` ตามหน้า headless ของ repo โดย **Headless mode is triggered when the CLI is run in a non-TTY environment** และมี exit code 0/1/42/53 [ยืนยัน] ([headless.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/headless.md)) แต่หน้านั้นไม่ได้อธิบายเรื่อง stdin หรือ auth

ทางเลือกอื่นคือ MCP `codex mcp-server` เปิด Codex เป็นเซิร์ฟเวอร์ MCP แบบ stdio พร้อมเครื่องมือ `codex` และ `codex-reply` [ไม่ยืนยัน: อ่านจาก mirror ของบุคคลที่สาม ชื่อคำสั่งต่างกันระหว่างแหล่ง] ([mirror docs/advanced.md](https://forge.lthn.ai/core/core-agent-ide/raw/commit/789e65b9d260ea5aa317a2e7dea80381cdcbde7e/docs/advanced.md)) คำสั่งผูกกับ Claude Code (`claude mcp add codex -- codex mcp-server`) เป็นข้อสันนิษฐานของผู้วิจัย ยังไม่เคยทดสอบ ปลั๊กอินสะพานอย่าง PAL MCP ที่มี `clink` (11.8k ดาว) เชื่อม Gemini CLI/Codex/Claude ได้ แต่ README เอ่ยถึงเฉพาะ API key ไม่ยืนยันว่าใช้ล็อกอิน subscription ของ CLI ได้ [ไม่ยืนยัน] ([PAL MCP](https://github.com/BeehiveInnovations/pal-mcp-server)) ส่วน Gemini CLI ไม่พบหลักฐานว่าเป็น MCP server ได้เอง มีเพียงโหมด ACP (`--acp`) สำหรับไคลเอนต์ IDE และสะพานชุมชนที่ยังไม่ได้ตรวจโค้ด [ไม่ยืนยัน]

ฟีเจอร์ agent teams ของ Claude Code **ไม่ใช่คำตอบ** เพราะ "Coordinate multiple Claude Code instances" คือประสานเฉพาะอินสแตนซ์ Claude ด้วยกัน กล่องจดหมายเป็นไฟล์ JSON ที่ `~/.claude/teams/{team-name}/inboxes/{agent-name}.json` และใน `-p`/Agent SDK "Claude doesn't spawn teammates" [ยืนยัน] ([Agent teams docs](https://code.claude.com/docs/en/agent-teams)) ไม่พบหลักฐานว่ารับเพื่อนร่วมทีมต่างค่ายได้ ส่วนโปรโตคอล ACP (Zed) และ A2A (Linux Foundation) มีอยู่จริง แต่ไม่พบการใช้ระหว่าง CLI เขียนโค้ดสามเจ้านี้ ([Zed ACP](https://zed.dev/acp), [A2A](https://github.com/a2aproject/A2A)) ข้อสรุป: subagent/skill/slash command ที่เรียก wrapper script ให้ผลกลับเป็น tool result ปกติ ซึ่งตรงกับที่คุณต้องการ (ส่งงาน รับคำตอบ สรุป) โดยไม่ต้องมีไฟล์กลาง ข้อดีของกล่องจดหมายแบบไฟล์ (ตรวจสอบย้อนหลังได้ ทนต่อการล่ม) ไม่คุ้มกับต้นทุนเพิ่ม (ต้องมี watcher ไม่มี auth ในตัว เสี่ยงไฟล์เขียนไม่ครบ) สำหรับกรณีของคุณ นี่คือการประเมินของผู้วิจัย ไม่มีบทความวิศวกรรมเปรียบเทียบรองรับ

มีโหมดล้มเหลวที่ต้องป้องกัน อย่างแรกคือ stdin ค้าง: Codex 0.118+ "reads stdin at startup and blocks forever on the open-but-empty pipe" จนครบ timeout 300 วินาที ทางแก้คือปิด stdin ด้วย `</dev/null` [ยืนยันในระดับ issue ของผู้พัฒนา wrapper ไม่ใช่เอกสาร OpenAI] ([codex_wrapper_ex #34](https://github.com/genagent/codex_wrapper_ex/issues/34)) อย่างที่สองคือ `agy -p` ที่ผู้ใช้หลายรายรายงานว่า "print timeout after 5m0s with turn in progress" ในเวอร์ชัน 1.2.x ถึง 1.4.10 ขณะที่โหมด interactive ใช้ได้ปกติ แม้ผู้ดูแลเคยบอกว่าปัญหาล้าสมัย ([antigravity-cli #318](https://github.com/google-antigravity/antigravity-cli/issues/318)) จึงต้องห่อทุกคำสั่งด้วย `timeout` เสมอ

## โควตาและล็อกอินไร้คนเฝ้า: สามกลุ่มโควตาแยกกัน และตัวเลขเปลี่ยนบ่อย

สามบัญชีมีโควตาแยกกัน การ fan-out จึงดึงจากสามกระเป๋า โดยกระเป๋า Claude จ่ายค่าโทเคนของการประสานและสรุปด้วย (ข้อสรุปนี้เป็นการอนุมาน) ฝั่ง Codex: README ยืนยันเพียงว่า Plus/Pro/Business/Edu/Enterprise รวม Codex [ยืนยัน] ส่วนตัวเลขอื่นเป็นแหล่งรองที่ขัดแย้งกันเอง [ไม่ยืนยัน] เช่น รายงานว่าเพดาน 5 ชั่วโมงของ Plus กลับมาตั้งแต่ 25 ส.ค. 2026 ขณะที่ Pro $100/$200 มีเพียงเพดานรายสัปดาห์ ประมาณการข้อความของ Plus ต่างกันมาก ("15 ถึง 80" เทียบกับ "30 ถึง 150" ข้อความต่อ 5 ชั่วโมง) และมีรายงานว่าเปลี่ยนไปคิดเป็นเครดิต/โทเคนตั้งแต่ เม.ย. 2026 ([Notebookcheck](https://www.notebookcheck.net/OpenAI-abruptly-restores-harsh-5-hour-Codex-and-Work-limits-for-ChatGPT-Plus.1378377.0.html), [aiidelist](https://aiidelist.com/blog/codex-5-hour-limit-plus-pro.md)) ฝั่ง Gemini ตารางในไฟล์ `quota-and-pricing.md` ของ repo ระบุ AI Pro 1,500 และ AI Ultra 2,000 คำขอต่อวัน และ "Requests are limited per user per minute" โดยไม่ระบุตัวเลขต่อนาที [ยืนยัน] ([quota-and-pricing.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/resources/quota-and-pricing.md)) แต่ไฟล์นี้น่าจะเก่ากว่าการปิดล็อกอินผู้บริโภค จึงอาจใช้ไม่ได้แล้ว และหนึ่งพรอมต์อาจกลายเป็นหลายคำขอ ส่วน Antigravity รีเฟรชทุกห้าชั่วโมง [ไม่ยืนยัน] ([Antigravity plans](https://antigravity.google/docs/plans.md)) ฝั่ง Claude Anthropic ไม่เผยจำนวนพรอมต์ และการเรียกแบบ `claude -p`/Agent SDK มีรายงานขัดแย้งว่าจะแยกเครดิตหรือไม่ [ไม่ยืนยัน] ([Zed blog](https://zed.dev/blog/anthropic-subscription-changes), [Startup Fortune](https://startupfortune.com/anthropic-quietly-separates-claude-agent-sdk-usage-from-subscription-limits/)) ดังนั้นควรจำกัดจำนวนครั้งและเวลาจริงเองใน wrapper

เรื่องล็อกอินแบบไร้คนเฝ้า Codex เก็บล็อกอินที่ `~/.codex/auth.json` หรือ keyring และเตรียมเครื่อง headless ได้สองทาง คือ `codex login --device-auth` (ต้องเปิดในการตั้งค่าความปลอดภัยของ ChatGPT) หรือล็อกอินบนเครื่องที่มีเบราว์เซอร์แล้วคัดลอก `auth.json` [ไม่ยืนยัน: จากสรุปผลค้นหาของ developers.openai.com/codex/auth] นอกจากนี้ระบุว่ารีเฟรชโทเคนอัตโนมัติขณะใช้งาน งานพร้อมกันหลายตัวที่ใช้ `auth.json` เดียวกันอาจแย่งกันรีเฟรช และเอกสารยังแนะนำ API key เป็นค่าเริ่มต้นสำหรับงานอัตโนมัติ (ทั้งหมด [ไม่ยืนยัน]) อายุ refresh token เมื่อเครื่องว่างหลายสัปดาห์ไม่มีแหล่งไหนยืนยัน ต้องวางแผนล็อกอินซ้ำเป็นครั้งคราว ฝั่ง Claude: Remote Control ต้องใช้ล็อกอิน subscription ("API keys are not supported"), เครื่องต้องเปิดและโปรเซส `claude` ต้องรันอยู่, ตั้ง `ANTHROPIC_BASE_URL` ไปโฮสต์อื่นแล้วใช้ไม่ได้ และโหมดเซิร์ฟเวอร์จะ "gives up after roughly 10 minutes" แล้วโปรเซสออกเมื่อเครือข่ายล่ม จึงต้องมี supervisor เช่น tmux/systemd รีสตาร์ต [ยืนยัน] ([Remote Control](https://code.claude.com/docs/en/remote-control)) อีกจุดหนึ่งคือ transcript ทั้งหมด รวมถึงคำตอบที่ Codex/Gemini ส่งกลับมา ถูกเก็บบนเซิร์ฟเวอร์ Anthropic ขณะเชื่อมต่อ [ยืนยัน] และ auto mode จะหยุดถามใหม่เมื่อ classifier บล็อก 3 ครั้งติดหรือ 20 ครั้งรวม ซึ่งในงานไร้คนเฝ้าหมายถึงค้างรออนุมัติ ([Permission modes](https://code.claude.com/docs/en/permission-modes)) Gemini ไม่มีเส้นทาง subscription ที่ทำงานไร้คนเฝ้าได้ตามเอกสารที่อ่านได้: OAuth ต้องใช้เบราว์เซอร์ และคำแนะนำของผู้ให้บริการคือ API key หรือ Vertex [ไม่ยืนยัน]

## ความปลอดภัย: ความเสี่ยงหลักคือ injection ที่ไหลกลับมาหา Claude

ภัยหลักคือข้อความไม่น่าเชื่อถือที่เอเจนต์หนึ่งอ่านแล้วไหลผ่านมายัง Claude ซึ่งมีสิทธิ์กว้างที่สุด Anthropic เองแนะนำให้ "Use virtual machines (VMs) to run scripts and make tool calls, especially when interacting with external web services" และยอมรับว่า "No system is completely immune to all attacks" [ยืนยัน] ([Security](https://code.claude.com/docs/en/security)) Remote Control ไม่มี sandbox: "No cloud VMs or sandboxing are involved" และโหมด `bypassPermissions` "offers no protection against prompt injection or unintended actions" ให้ใช้เฉพาะในคอนเทนเนอร์/VM ที่ไม่มีอินเทอร์เน็ต [ยืนยัน] ([Permission modes](https://code.claude.com/docs/en/permission-modes)) Claude Code ปฏิบัติต่อข้อความจากเอเจนต์อื่นอย่างระวังอยู่แล้ว (teammates "can't approve a permission prompt or supply consent on your behalf") [ยืนยัน] ([Agent teams docs](https://code.claude.com/docs/en/agent-teams)) แต่ไม่พบคำแนะนำของผู้ให้บริการที่เจาะจงเรื่องสายโซ่ injection ระหว่างสามเจ้า

มาตรการที่เสนอ (ข้อเสนอของผู้วิจัย ไม่ใช่คำแนะนำทางการ): (1) เขียน wrapper เช่น `bin/ask-codex.sh` ที่ล็อก flag ของ sandbox แบบ read-only, ปิดเครือข่าย, ใส่ `timeout`, ใส่ `</dev/null`, กำหนด cwd เป็น worktree/สำเนาชั่วคราวที่ไม่มี `.env` และไม่มี remote ที่ push ได้ แล้วอนุญาต Claude เฉพาะ `Bash(./bin/ask-codex.sh *)` คู่กับ `dontAsk` ซึ่งเอกสารนิยามว่า "auto-denies every tool call that would otherwise prompt you" เพื่อไม่ให้ค้างรอ (2) ห่อผลลัพธ์ของอีกฝั่งด้วยตัวคั่นและสั่ง Claude ให้ถือเป็นข้อมูล ไม่ใช่คำสั่ง (3) ให้ Codex ทำหน้าที่ที่ปรึกษา/รีวิวแบบอ่านอย่างเดียว ให้เฉพาะ Claude เขียนไฟล์ (4) แยกผู้ใช้ OS หรือคอนเทนเนอร์ เพราะเอเจนต์ที่รันเป็นผู้ใช้เดียวกันอ่าน `~/.codex`, `~/.gemini`, `~/.claude` ของกันและกันได้ และ Codex เก็บโทเคนเป็นไฟล์ธรรมดา (5) บันทึก JSONL ทุกการเรียกไว้นอกแผนผังงาน (6) ห้ามเปิด Codex `--dangerously-bypass-approvals-and-sandbox`, `danger-full-access` ร่วม `never`, Gemini `--yolo` บนโฮสต์ และ `bypassPermissions` บนโฮสต์ ชื่อ flag ฝั่ง Codex/Gemini ที่กล่าวถึงยังไม่ได้ตรวจกับเอกสารหลัก ยกเว้นว่า Gemini รองรับ `-s/--sandbox` และ `GEMINI_SANDBOX=true|docker|podman|sandbox-exec|runsc|lxc` ซึ่งยืนยันจาก `sandbox.md` ของ repo [ยืนยัน] ([sandbox.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/sandbox.md)) ข้อมูลดังกล่าวเป็นข้อมูลของโปรเจกต์นี้ด้วย: AGENTS.md ห้ามคอมมิต `.env` และกุญแจ LINE/Anthropic จึงต้องไม่อยู่ในไดเรกทอรีที่เอเจนต์ภายนอกมองเห็น

## ความเสี่ยง ToS และการแบน: Google สูงสุด Anthropic กลาง OpenAI กำกวม

หลักคิดร่วมคือ **การรันไบนารีทางการของแต่ละเจ้าบนเครื่องคุณเองด้วยบัญชีของคุณ เป็นรูปแบบที่ปลอดภัยที่สุด ส่วนการดึงโทเคน OAuth ไปให้เครื่องมือบุคคลที่สามเป็นตัวกระตุ้นการแบน** ไม่พบรายงานการแบนจากการเชื่อม CLI ทางการด้วย Bash เพียงอย่างเดียว แต่นั่นคือการไม่พบหลักฐาน ไม่ใช่การยืนยันว่าปลอดภัย (นี่เป็นข้อสรุปของผู้วิจัย)

Anthropic: หน้ากฎหมายของ Claude Code ระบุว่า OAuth "is designed to support ordinary use of Claude Code and other native Anthropic applications" ไม่อนุญาตให้นักพัฒนาบุคคลที่สาม "route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users" ผู้ใช้ Agent SDK ควรใช้ API key และ "Advertised usage limits ... assume ordinary, individual usage" พร้อมสงวนสิทธิ์บังคับใช้โดยไม่แจ้งล่วงหน้า แต่ก็ระบุว่าไม่มีอะไรห้ามผู้ใช้ปลายทางล็อกอินไบนารี Claude Code ที่ไม่ถูกแก้ไขด้วยบัญชีตนเอง [ยืนยัน] ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)) ไม่พบข้อความของ Anthropic ที่กล่าวถึงการที่ Claude Code เรียก CLI ของเจ้าอื่นโดยตรง ความเสี่ยงฝั่ง Anthropic จึงอยู่ที่วิธีขับ Claude เอง (loop แบบ `claude -p` ถือเป็นพื้นที่สีเทา) รายงานการบล็อกโทเคน OAuth ในเครื่องมือบุคคลที่สามตั้งแต่ 4 เม.ย. 2026 เป็นแหล่งรอง [ไม่ยืนยัน] ([TNW](https://thenextweb.com/news/anthropic-openclaw-claude-subscription-ban-cost))

OpenAI: ไม่พบข้อความจากเอกสารหลักเลย อ่านได้เพียงว่าเงื่อนไขการใช้งานมีถ้อยคำเรื่องการดึงข้อมูล "automatically or programmatically" และพนักงาน OpenAI ยอมรับในดิสคัสชันว่า Codex CLI เองก็ส่งคำขอเชิงโปรแกรม โดยยังไม่เห็นข้อความที่อนุมัติการใช้ OAuth กับบริการบุคคลที่สาม [ไม่ยืนยัน] ([openai/codex Discussion #8338](https://github.com/openai/codex/discussions/8338)) มีรายงานว่าหัวหน้า Codex ระบุว่าไคลเอนต์บุคคลที่สามที่ใช้ Sign in with ChatGPT ไม่ใช่การใช้ที่อนุมัติ เว้นแต่เป็นพันธมิตรหรือโอเพนซอร์สล้วน [ไม่ยืนยัน] ([AICoder](https://www.aicoder.com/news/news-20260908-openai-codex-sign-in-policy)) การเรียกไบนารี `codex` ทางการโดยสคริปต์ของคุณเองจึงอยู่ฝั่งปลอดภัย แต่ยังไม่มีนโยบายทางการเรื่อง `codex exec` อัตโนมัติ

Google: หน้า ToS ของ Gemini CLI ระบุว่าการเข้าถึงบริการผ่าน "third-party software, tools, or services" (ตัวอย่าง "using OpenClaw with Gemini CLI OAuth") "is a violation of applicable terms and policies" และอาจ "grounds for suspension or termination of your account" [ยืนยัน] ([tos-privacy.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/resources/tos-privacy.md)) ผู้ดูแลโพสต์เมื่อ 27 ก.พ. 2026 ว่ามีการแบนเพราะ "use of 3rd party tools or proxies to access Antigravity resources and quotas" การแบนบล็อก Gemini CLI และ Gemini Code Assist ด้วย และ "If an account is flagged for a second violation of ToS, it will be permanently banned" [ยืนยัน] ([Discussion #20632](https://github.com/google-gemini/gemini-cli/discussions/20632)) รายงานผู้ใช้ระบุว่าบัญชี Pro และ Ultra ที่จ่ายเงินก็โดน [ไม่ยืนยัน] ([openclaw #14203](https://github.com/openclaw/openclaw/issues/14203)) เจ้าหน้าที่ฟอรัมที่ระบุว่าการครอบ `agy` ด้วยเอเจนต์อย่าง Claude Code ภายใต้ล็อกอินผู้บริโภค "ไม่รองรับ" และอาจถูกระงับ ก็เป็นแหล่งรองเช่นกัน และเจ้าหน้าที่เองบอกว่าตีความกฎหมายอย่างเป็นทางการไม่ได้ [ไม่ยืนยัน] ([forum thread](https://discuss.ai.google.dev/t/is-google-ai-pro-antigravity-cli-automation-with-codex-permitted/187241)) ขอบเขตการแบน (เฉพาะ Gemini/Antigravity หรือทั้งบัญชี Google) ยังไม่ยืนยัน ให้ถือเป็นความเสี่ยงต่อบัญชีหลักจนกว่าจะพิสูจน์ได้ว่าไม่ใช่

## สถาปัตยกรรมแนะนำ: ผู้ประสานเดียว ที่ปรึกษาอ่านอย่างเดียว และทางเลือกที่ถูกกว่า

ลำดับชั้นของทางเลือก (เรียงจากควรเริ่มก่อน) มีดังนี้ ทางเลือก A คือ Claude อย่างเดียว ใช้ subagent โมเดลเล็กแบบอ่านอย่างเดียว (auto mode รองรับ Haiku 5.5 ตามเอกสาร [ยืนยัน]) ชนะเรื่องต้นทุน ความง่าย และไม่เพิ่มบัญชี แต่ subagent ใช้โควตา Claude ก้อนเดียวกัน [ไม่ยืนยัน] ทางเลือก B คือ Claude + Codex เป็นที่ปรึกษารีวิวอิสระ เหมาะเมื่อต้องการความเห็นจากโมเดลต่างค่ายจริง ๆ และโมเดล sandbox ของ Codex ได้รับการอธิบายดีกว่าของ Gemini ในแหล่งที่พบ ทางเลือก C คือ fan-out เต็มรูปแบบสามเจ้า คุ้มเฉพาะการตัดสินใจเดิมพันสูงที่ความเห็นต่างข้ามโมเดลมีค่า และต้องใช้ API key สำหรับ Gemini ทางเลือก D คือย้ายไปรันบน cloud session เพื่อไม่ต้องเปิดเครื่องบ้าน แต่การล็อกอิน subscription ของ CLI อื่นใน VM ยังไม่ยืนยัน ทางเลือก E คือใช้ API key ให้ Codex/Gemini ขณะ Claude ยังอยู่บน subscription (Remote Control บังคับ) ได้ auth ที่เอกสารรองรับและคาดเดาได้ แต่เสียเงินตามใช้ ซึ่งขัดข้อกำหนดของคุณ

แผนที่แนะนำสำหรับข้อกำหนด "ไม่ใช้ API": ติดตั้งเส้นทาง B ก่อน โดยรัน `claude` ภายใต้ supervisor (tmux/systemd, ปิดการหลับของเครื่อง, ไม่ตั้ง `ANTHROPIC_API_KEY` หรือ `ANTHROPIC_BASE_URL`, ใช้ `--capacity` ต่ำและ `--spawn worktree`) สร้าง skill หรือ subagent `ask-codex` ที่เรียก wrapper เดียว ให้ wrapper คืนผลเป็น JSON มีโครง `{vendor, status, answer, duration}` และคืนสถานะ "vendor unavailable" แทนการลองซ้ำเมื่อพบ 429 ผลลัพธ์ว่าง หรือ exit code ไม่ใช่ศูนย์ เพิ่มตัวนับรายวันที่ปฏิเสธเมื่อเกินเพดาน serialize การเรียก Codex ด้วย mutex ป้องกันแย่งรีเฟรชโทเคน และรัน health-check ราคาถูกวันละครั้งเพื่อแจ้งเตือนเมื่อล็อกอินหลุด ในด้าน Gemini ให้เลื่อนออกไปหรือใช้ API key จนกว่า Google จะออกเอกสารที่ชัดว่า `agy -p` ที่ถูกเรียกโดยเอเจนต์ภายนอกภายใต้ล็อกอินผู้บริโภคได้รับอนุญาต ขั้นตอนตรวจสอบก่อนใช้งานจริงอยู่ในตารางด้านล่าง

| รายการที่ต้องตรวจก่อนลงมือ | สถานะหลักฐาน | หน้าที่ต้องเปิดเอง |
|---|---|---|
| flag ของ `codex exec` (sandbox/approval/`--json`/`-o`) | ไม่ยืนยัน | developers.openai.com/codex/noninteractive |
| อายุ refresh token ของ Codex เมื่อไม่ใช้งานนาน | ไม่ยืนยัน | developers.openai.com/codex/auth |
| นโยบาย OpenAI เรื่อง `codex exec` อัตโนมัติ | ไม่พบเอกสารหลัก | OpenAI Terms of Use, Service Terms |
| ตัวเลขโควตา Codex/Antigravity ปัจจุบัน | ไม่ยืนยัน/ขัดแย้ง | developers.openai.com/codex/pricing, antigravity.google/docs/plans |
| ขอบเขตการแบนของ Google และ Antigravity Additional Terms | ไม่ยืนยัน | หน้าเงื่อนไข Antigravity |
| การคิดเงิน `claude -p`/Agent SDK ณ พ.ย. 2026 | แหล่งรองขัดแย้ง | ศูนย์ช่วยเหลือของ Anthropic |

## บทสรุป

ข้อค้นพบที่เปลี่ยนภาพคือ คำถาม "Claude สั่ง GPT และ Gemini ผ่าน subscription ได้ไหม" แตกเป็นสองคำถามที่คำตอบต่างกัน: เส้นทาง Codex ใช้ได้ทั้งทางเทคนิคและเสี่ยงต่ำถ้าเรียกไบนารีทางการเอง ส่วนเส้นทาง Gemini ถูกปิดในเชิงผลิตภัณฑ์ (ล็อกอินผู้บริโภคย้ายไป Antigravity ตั้งแต่ 18 มิ.ย. 2026) และถูกปิดในเชิงนโยบาย (Google แบนจริงและเขียนไว้ใน ToS) ดังนั้นคอขวดของโครงการไม่ใช่ "จะให้เอเจนต์คุยกันอย่างไร" ซึ่งแก้ได้ด้วย wrapper script ไม่กี่สิบบรรทัด แต่คือ "ผู้ให้บริการยินยอมให้ใช้ล็อกอิน subscription ในลูปอัตโนมัติหรือไม่"

ข้อควรระวังที่ต้องพูดตรง ๆ คือ รายงานนี้ยังไม่ได้ทดสอบ end-to-end สักเส้นทางเดียว และเกือบทุกข้อเท็จจริงฝั่ง OpenAI และ Google ที่เกี่ยวกับโควตา auth และ flag ยังไม่ผ่านการตรวจกับเอกสารหลัก ควรเปิดหน้าตามตารางข้างต้นด้วยเครือข่ายที่เข้าถึงได้ และทดลองเส้นทาง B ในสภาพแวดล้อมแยกก่อนผูกกับโปรเจกต์ ClimateRisk-AILab ซึ่งมีกุญแจ LINE และ Anthropic ที่ต้องกันไม่ให้เอเจนต์ภายนอกมองเห็น
